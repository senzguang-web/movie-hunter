覆盖范围：24 部电影均已核验 IMDb 与 Rotten Tomatoes 评分，并附 RT 影评人共识的中文转述。

来源与口径：

- IMDb 为平台显示的加权用户评分。
- Rotten Tomatoes 为 Tomatometer（获认可影评人给出正面评价的比例），不是观众 Popcornmeter，也不是十分制均分。
- Metacritic 为 Metascore（专业评论评分），不是 User Score。
- 豆瓣只录入实际看到的条目评分。部分主条目跳转安全验证，因此留空。保留已确认电影身份的页面链接，不绕过访问限制。
- 触不可及的 IMDb 8.5 另见 [IMDb 官方条目](https://www.imdb.com/title/tt1675434/business)。
- IMDb 部分直接访问返回 403；采用搜索服务返回的官方页面正文。Perfect Days 的 7.9 也见于 [IMDb 西语官方条目](https://www.imdb.com/es/title/tt27503384/?bypassRefViewPref=1)。
- Metacritic 的直接访问受到 robots 限制；采用搜索引擎返回的对应官方电影条目评分，不把 IMDb 转引当作 Metacritic 的独立核验。
- 搜索时遇到同名作品已排除：Coco 使用 Pixar 的 `tt2380307`，而非同年的恐怖片 `tt7002100`；Perfect Days 使用文德斯的 2023 年电影，而非 2025 年剧集。
- 龙猫的 Rotten Tomatoes 有重复条目，使用带评分及影评人共识的 [My Neighbor Totoro](https://www.rottentomatoes.com/m/my_neighbor_totoro)，其页面年份显示美国发行信息；不是没有评分的 `_1988` 条目。

## 后续接入 OMDb

[OMDb 官方文档](https://www.omdbapi.com/)提供按 IMDb ID (`i`) 或片名 (`t`) 查询电影信息的接口，所有数据请求需要 `apikey`。[官方 API Key 页面](https://www.omdbapi.com/apikey.aspx)显示免费方案每日 1,000 次请求，需要通过邮箱申请。官方文档支持 HTTPS；密钥应只放在服务端环境变量中，并对电影 ID 查询结果设置缓存。

[官方仓库 issue #102](https://github.com/omdbapi/OMDb-API/issues/102)保留的 API 响应示例含 `Ratings` 数组，其 `Source` 可包括 `Internet Movie Database`、`Rotten Tomatoes` 和 `Metacritic`。这是历史响应证据，并不保证每部电影或当前每次响应都含全部评分；同一例子中 `tomatoConsensus` 等字段为 `N/A`。未获得用户的 API Key，未执行已鉴权实时请求。应把缺失评分正常显示为不可用，不承诺能获取完整评论正文。
